# Insertion-cell array (cell sort)

The par design for the sorter: an array of `N` insertion cells adapted from an open-source, MIT-licensed cell-sort design (the header keeps the licence and lists every change with its reason), proved with latency `2N` for every `N, W ≥ 1` with `N·W < 2^31`.

## The idea

Each cell holds one `W`-bit value, and cell `N-1` is the top. While values stream in, every cell compares the broadcast input `x` with its own value and its upper neighbour's. If `x` beats the neighbour, the cell takes the neighbour's value, so everything below the insertion point shifts down; else if `x` beats its own value it takes `x`; else it holds. The cells stay sorted, with zero padding at the bottom. When the input stops, every cell shifts down and the top takes 0, so the minimum leaves through cell 0 into a registered `out_data`, one value per cycle. A one-bit token per cell, shifted down with `in_valid` entering at the top, makes `out_valid` the input's valid delayed by `N`. `start` is not read. After the last output every cell is 0 again, so back-to-back transactions need nothing.

The adaptation made one flat module with the task's ports, turned the cells into a generate family over one packed vector, folded the wires into the `always_ff` bodies so every process is a flop process, and added the streaming output and the tokens.

## Why it scores as it does

The latency is `N` cycles to load and `N` to drain, one cycle above the bound `2N - 1` because the output is registered. At `N = W = 8` on sky130 the design is about 5,513 µm² in 713 cells, 81 of them flip-flops, with a 2,523 ps period: 16 × 2,523 ps and about 222,540 µm²·ns, which is par. On ASAP7: about 88.4 µm² at 536 ps, 758.1 µm²·ns.

## The proof

774 lines through the stream-task reduction `StreamTask.satisfiedAtV2_of_phases`, which needs one clock cycle in closed form and a phase model:

1. Agreement (`so_sem_eq`): the loaded design is a hand-built `soD`.
2. The clock step: every process is an `always_ff`, so the library's flop-only profile gives a cycle as a commit of the update queues `topQ`, `outQ` and `cellQ` (`so_profile`, `so_cycle`); a reset's write wins (`next_reset`).
3. The sort: a load is `tail ∘ insertAsc x` on ascending cells (`hw_ins`); insertions commute (`ins_comm`), hence `sort_snoc`; the dropped head is a padding zero (`tail_ins`).
4. The invariant `j` cycles after a start: cells `cv`, tokens `tokv`, output valid `ovb`, advanced by `at_step`.
5. The phase model `model`, with phases `Ready` and `At ys j`; the Moore, x-safety and power-up obligations close by `simp` and `powerUp_cons`.
