# One AND gate per bit

The par design of the toy task: `band.sv` is a single continuous assign, `assign y = a & b;`, one two-input AND gate per bit for every width `N`. The maintainers recorded it as par, with `band.lean`, a proof that walks the design's instantiation by hand instead of using the `sv_comb` tactics.

## The idea

There is no trick to find. The function is bitwise, so each output bit is one gate of its own two input bits and no bit depends on another. The task exists to exercise the whole pipeline (statement, proof, checker, banlist, scoring) on a design whose optimum is obvious, and the task README states that this design is optimal.

## Why it scores as it does

At the scoring point `N = 16` the netlist is 16 `and2_1` cells: 100.1 µm² of sky130 area, and a critical path one cell deep, 280 ps to `y[0]`. Area times time is 28.03 µm²·ns, which is par. In the extra columns it is 21.3 NAND2 gate equivalents at depth 1. On the routed ASAP7 course it measures 1.40 µm² and 25 ps.

## The proof

The proof is 159 code lines in four steps, and its tactic census is just `simp`, `omega` and `decide`:

1. **The design at symbolic `N`.** `band_instantiate2` splits instantiation into its stages with `PDesign.instantiate2_of_ok`: the parameter environment by `rfl`, the declarations and element widths by `simp`, the one static process by `sv2_inst_simp`. The one-driver guard is closed data, so `band_driversOk` is a `decide`, and `band_sem_eq` identifies `design.sem N` with the instantiated design.
2. **Comb profile and acyclicity.** `band_comb` fills the `CombDesign` structure field by field: no duplicate declarations, the one write window of `y` in range and not an input, every read declared. `band_acyclic` uses the constant rank 0, since the assign reads only `a` and `b`, which nothing writes.
3. **The settled state.** `band_settled` applies `CombEqs.lookup_ident` with the evaluation lemmas for identifiers and `&` on known bit vectors: in any solution of the equations, known `a` and `b` give `y = a &&& b`.
4. **The statement.** `solution` reduces the task's statement to the interface and step 3 with `CombTask.satisfiedAt_of_comb`.

The same design also has a 38-line proof with the `sv_comb` tactics (`sv_structure`, `sv_interface`, `sv_equations`), which the site's walk-through follows. This longer file shows what those tactics automate.
