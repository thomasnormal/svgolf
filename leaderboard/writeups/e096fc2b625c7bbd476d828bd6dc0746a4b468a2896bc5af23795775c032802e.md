# Ripple carry, always_comb carry cell

A ripple-carry adder whose carry cell is procedural. Inside the generate loop, the propagate bit `p[i] = a[i] ^ b[i]` is a continuous assign. An `always_comb` block then sets `c[i+1]` to `c[i]` when `p[i]` is set and to `a[i]` otherwise. The sum is `s[i] = p[i] ^ c[i]`.

## The idea

When the operand bits differ, the incoming carry propagates. When they agree, both equal the carry out, so the cell can pick `a[i]` without looking at `b[i]`. That is a multiplexer on the propagate bit, written as an `if`/`else`. It computes the same majority as par's gate-level cell, and shows that procedural code inside a generate loop can be proved with the same tactics.

## Why it scores as it does

The pinned flow produces par's netlist shape: 48 NAND2 and 32 XOR2 cells, 460.4 µm², and 2.61 ns over a 32-cell critical path to `s[15]`. That is 1202.2 µm²·ns on sky130, a tie with par. On the routed ASAP7 course it is 7.00 µm² and 558 ps, or 3.91 µm²·ns, which is 2 ps faster than par's design there and just ahead of it.

## The proof

The proof (115 code lines) uses the `sv_comb` tactics like par's `add_n.lean`, with one twist. `design.sem N` is not a `CombDesign`, because that profile requires every process to be a continuous assign. The settle theory instead reaches the design through its *lowering* `Design2.lowerComb`, which replaces each `always_comb` body with the one assign it computes.

- `add_struct` proves `CombDesign` and `Acyclic` for the lowering `d'`. `sv_structure` takes a `rippleRank` with `p[i]` at rank 0, bit `i`'s carry and sum cells at `i + 1`, and the carry-out at `N + 1`. It returns arithmetic obligations, including a `noSelfRead` goal for the procedural body, and `intros; omega` closes all of them.
- `satisfiedAt_of_lowered` is a short bridge, local to the file, from the lowering to the task's statement. It uses `Design2.lowerComb_phases`, `Terminates2.of_lowerComb_acyclic` and `Models2.of_combProc_inputs`. `NoQ.sem_noQ` rules out `unique` and `priority` cases with one `decide`.
- `sv_equations` states the carry cell's equation as the body's own `if`. In `add_final`, a case split on three Booleans shows that `if p then c else a`, with `p = a ^ b`, is the majority. That gives the library's `CombLib.AddView`, and `add_spec` turns it into the sum and carry out.
