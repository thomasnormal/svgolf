# Processing in memory, plain signed multiply

`bank_mac_mul.sv` models processing in memory: N memory banks, each with one multiply-accumulate unit at its edge, driven by one sequencer that issues one DRAM-style command per cycle to every bank. It is the same machine as `bank_mac.sv`, except that each unit uses a plain signed product instead of an unsigned product with a correction.

## The idea

At the start edge, row r of A is written into array row 0 of bank r, sign-extended to AccW bits. The sequencer then runs a fixed program:

1. `ACT0` opens that row into the row buffer.
2. For each column j of B, `FILL` broadcasts the column into every unit's register file and clears the accumulator. N `RD` commands follow, each adding the product of column 0 of the row buffer and entry 0 of the register file, while both rotate.
3. `LAST`, `ACT1`, `WR` and `PRE` write the results back through the row buffer into array row 1.
4. `READ` copies that row to C and raises `done`.

There are N multipliers, and the latency is N² + N + 6, which is 26 at N = 4. The multiply is the AccW-bit A entry times the B entry sign-extended to AccW bits, the reference's form.

## Why it scores as it does

On sky130 the design is 162,446 µm² with 2,658 flip-flops, the same storage as its sibling. The full-width sign-extended operand costs 14,510 µm² more than the sibling and a longer period, 10,707 ps against 9,713 ps. The cell counts show it too: 2,328 `xor2` cells against 1,325. Twenty-six cycles take 278,382 ps. The score is about 45.22 million µm²·ns: 12.125 × par on sky130 and 12.794 × par on ASAP7. The serial schedule, with one multiplier per bank, makes this the slowest matmul design on the board.

## The proof

The proof has 1,664 code lines and the same shape as the sibling's:

- agreement with a hand-built design (`mm_sem_eq`) and the clock step (`mm_cycle`);
- program-position predicates (`AtAct0`, `AtFill j`, `AtRd j k`, `AtLast`, `AtTail`, `AtPre`, `AtRead`) that give every register's value;
- their disjunction `BusyAt m`, which carries the remaining cycle count;
- `busy_step`, built from one lemma per command, `step_act0` to `step_read`.

The multiply-accumulate step needs only `mac_arith`: truncating a wide accumulate of a sign-extended product gives the AccW-bit signed multiply-accumulate. The sibling needs a further correction lemma. `mac_val` turns the step into the partial sum `psum (k + 1)`, and the phase model and the three rules finish the proof as in the reference.
