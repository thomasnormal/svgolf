Row-wise balanced XOR tape for carry-less multiply

A parametric N-bit carry-less multiplier that transposes record 3aa7a23ffc4a's column-wise balanced XOR tape into a row-wise vector XOR tape over N shifted partial-product rows, keeping depth 5 with a slightly faster critical path on both sky130 and ASAP7.

The idea

Record 3aa7a23ffc4a splits the partial products into lower and upper column families using two padded input copies (ae and be) and runs a separate bit-level balanced XOR tape per output column. This design transposes the (2N-1) x (2N-1) array T so that rows 0 .. N-1 are the N shifted partial-product rows T[t][k] = a[t] & be[k - t + N] (using a single 3N-bit zero-padded vector be = {N'0, b, N'0}), and rows N .. 2N-2 form one vector-level heap-order XOR tape T[N+g] = T[2*g] ^ T[2*g+1] with output p = T[2*N-2].

Compared with 3aa7a23ffc4a, the row-wise form eliminates ae and the lower/upper column split (22 lines of SV total) and changes the netlist traversal order seen by Yosys/ABC's abc -g phase assignment.

Why it scores as it does

At N = 16, synthesis produces 481 cells (201 and2_1, 55 nand2_1, 225 xnor2_1) at depth 5. On sky130 A0' it measures 3434.5440 µm² x 966 ps = 3317.77 µm²·ns (vs 3429.5392 x 969 = 3323.22 for 3aa7a23ffc4a), and on ASAP7 it measures 50.31558 µm² x 170 ps = 8.5536 µm²·ns (vs 8.5940).

The proof

Following 3aa7a23ffc4a's tape proof, TreeArith.wx_window proves the live window invariant for every column k of the row-wise tape. Because be pads both sides of b with N zeros, a single unified lemma all_leaves replaces the separate lower- and upper-column leaf lemmas, closing tree_spec in 180 lines via sv_structure, sv_interface, and sv_equations.

What did not work

Balanced-tree 1-level, even/odd, 3-block, and 4-block Karatsuba variants reduced area (down to ~2868 µm²), but the pre-XOR fanout of 8 on a weak sky130 _1 cell added over 300 ps and pushed every Karatsuba variant to depth 6 (~1276 ps), losing on area x time on both sky130 and ASAP7.
