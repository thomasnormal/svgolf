# Ripple carry, XNOR-selected multiplexer carry

A ripple-carry adder written with `~` and the conditional operator instead of AND/OR gates. For each bit, `e[i] = ~(a[i] ^ b[i])` tests whether the operand bits are equal, the carry is `c[i+1] = e[i] ? a[i] : c[i]`, and the sum is `s[i] = ~(e[i] ^ c[i])`.

## The idea

If the operand bits are equal, the carry out is their common value, whatever the carry in is. If they differ, the carry in passes through. So the carry cell is a two-way multiplexer selected by an XNOR, and the sum reuses the same XNOR, inverted once more. It is the same majority function as par's cell, written as a selection rather than as gates.

## Why it scores as it does

The pinned flow maps the `?:` carry to the same netlist as par's gates: 48 NAND2 and 32 XOR2 cells, 460.4 µm², and a 32-cell critical path to `s[15]` at 2.61 ns. That is 1202.2 µm²·ns on sky130, a tie with par. It also matches par on the routed ASAP7 course, at 7.00 µm², 560 ps and 3.92 µm²·ns. The task README notes this effect in general: the flow restructures what is written, and a multiplexer carry comes out as the same three NAND gates per bit as the reference.

## The proof

The proof is 97 code lines and follows the intended tactic route with no detours. Unlike the `always_comb` variants, every process here is a continuous assign, so `design.sem N` is itself a `CombDesign`:

1. `add_struct` calls `sv_structure` once to prove `CombDesign` and `Acyclic`, using the player's rank. The carry-in gets 0, bit `i`'s three cells get `3i + 1` to `3i + 3` in source order, and the carry-out gets `3N + 1`. Every obligation closes with `intros; omega`.
2. `add_interface` is one line of `sv_interface`.
3. `sv_equations` derives the netlist's equations over `Bool` under stable names: `eq_c_1` (`c[0] = cin`), `eq_e_1` (the XNOR), `eq_c_2` (the carry cell, read as an `if` on `e[i]`), `eq_s_1` and `eq_cout_1`. It also proves every driven bit is known. The side goals close by `omega`, `sv_cover` and `inKnown_ofBitVec`.
4. `add_final` holds the only mathematics. Two case splits over three Booleans show that the multiplexer is the majority and that the double XNOR is the parity. Together these give `CombLib.AddView`, `add_spec` yields the sum, and `SvState.lookup_eq_ofBitVec_bv` turns the bits back into port values.
