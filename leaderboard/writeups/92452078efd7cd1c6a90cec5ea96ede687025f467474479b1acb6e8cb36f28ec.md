# One AND gate per bit, with localparams

The same circuit as par's design, one AND gate per bit, written with local parameters. The module header declares `localparam int W = N` after the task's parameter and sizes all three ports with `W`. The body declares `localparam int MSB = W - 1`, which nothing reads. The assign itself is unchanged: `assign y = a & b;`.

## The idea

This entry is about the interface, not the circuit. The task fixes the parameter list to `N`, but localparams are the design's own business, and the checker compares only the overridable parameters with the task. `MSB = W - 1` is constant arithmetic, so it passes the toy task's banlist, which bans `+ - * / % **` only on run-time operands. The design shows that a player may name derived widths freely without leaving the statement.

## Why it scores as it does

Synthesis sees straight through the localparams. The netlist is the same 16 `and2_1` cells as par's: 100.1 µm² and 280 ps on sky130, with one cell on the critical path, for 28.03 µm²·ns. On the routed ASAP7 course it is 1.40 µm² and 25 ps. It ties par on both courses.

## The proof

The proof (161 code lines) is par's by-hand proof with one definition changed: `bandScope`, the parameter environment that the instantiation is computed in. It now binds `MSB` to `N - 1` and `W` to `N` after `N`, each as a 32-bit `int`. Everything downstream goes through unchanged, because `band_paramEnv` is still `rfl` and the declaration stage still evaluates every port width to `|N - 1| + 1`:

1. `band_instantiate2` and `band_sem_eq` give the design at symbolic `N`. The one-driver guard is decided on the closed process list.
2. `band_comb` proves the comb profile field by field, and `band_acyclic` proves there is no loop with the constant rank 0.
3. `band_settled` gets `y = a &&& b` from `CombEqs.lookup_ident` and the evaluation lemmas for known bit vectors.
4. `solution` closes the statement with `CombTask.satisfiedAt_of_comb`.

Because only the environment moves, the file also serves as a regression test for the checker: localparams, in the header or in the body, must not be mistaken for task parameters.
