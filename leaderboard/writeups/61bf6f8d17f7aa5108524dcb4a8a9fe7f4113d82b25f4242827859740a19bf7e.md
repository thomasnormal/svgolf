# Insertion-cell array, input test first

The reference insertion-cell sorter `sorter_ins.sv` with each cell's conditions rewritten. It has the same registers, the same latency `2N` (16 cycles at `N = W = 8`) and the same behaviour, but a smaller netlist and a faster clock.

## The idea

In the reference, a cell receiving input `x` first asks whether its upper neighbour is pushed out (`x > d1`) and if so takes the neighbour's value; otherwise it takes `x` if `x` beats its own value (`x > d0`), and otherwise holds. With no input it shifts down. This design tests the take-input case first, `in_valid && !(d1 < x) && d0 < x`, and then shifts on `!in_valid || d1 < x`. The two tests cannot both hold, so swapping the order of the branches does not change the function. Every comparison is written `d < x`. The top cell and the output register are unchanged.

## Why it scores as it does

What changes is what synthesis makes of each cell's select: the netlist has only 7 MUX2 cells among its 697 cells, 81 of which are flip-flops (64 cell bits, 8 tokens and the output register, as in the reference). On sky130 the area is about 4,755 µm² against par's 5,513, and the period 2,064 ps against 2,523. Over 16 cycles that is 33,024 ps and about 157,015 µm²·ns, 0.71 × par. On ASAP7 it is about 76.9 µm² with a 491 ps period, 604.4 µm²·ns against the reference's 758.1.

## The proof

The proof is the reference's, 816 lines against 774, with only the cell process and its evaluation changed. The two tests are opaque definitions (`cxE`, `csE`, marked `@[irreducible]`) with evaluation lemmas (`ev_cx`, `ev_cs`) that compute them under the 4-state `&&`, `||`, `!` and `<` (`xV`, `sV`), so the cell's one-cycle lemma splits on the two test values rather than on the comparisons inside them. Two pairs of lemmas then reduce the tests. With `in_valid = 0` the first fails and the second holds whatever the data (`cX_false`, `cS_false`). With `in_valid = 1` and known data they are the plain comparisons (`cX_known`, `cS_known`).

Plugged into the cell's next-state lemma, these give exactly the reference's next state. Everything after that is reused unchanged: the sort lemmas (`hw_ins`: a load is `tail ∘ insertAsc x`; `ins_comm`: insertions commute), the invariant (`cv`, `tokv`, `ovb`) and the phase model for `StreamTask.satisfiedAtV2_of_phases`.
