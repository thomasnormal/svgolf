# Baselines for task `clmul` (NOT entries)

Reference points for the (area, depth) frontier at the task's scoring flow (`score/score.py`, Yosys 0.53 + ABC).
None of these is an svGolf entry: each is a flat netlist for ONE width (it keeps the task header, but at any
other `N` it is wrong, so it cannot satisfy the for-all-`N` statement), generated by `gen_clmul.py`:

* `school_tree_<N>.sv`: the schoolbook product, all `N^2` partial products `a[i] & b[j]`, then column `k = i + j`
  summed by a balanced tree of XORs.
* `kara_b<B>_<N>.sv`: Karatsuba, `p = L + x^m (M + L + H) + x^2m H` with `m = N / 2` and the three half-size
  products `L = aL (x) bL`, `H = aH (x) bH`, `M = (aL + aH) (x) (bL + bH)` (sums are XORs), recursing down to a
  schoolbook product on at most `B` bits; `kara_full_16.sv` recurses to 1 bit.

`gen_clmul.py --write` regenerates every file here and `--check` verifies them (`tests/run.py` does). THE
EMISSION ORDER IS THE CANON: ABC's result for a flat netlist depends on the order of its assigns (the
`aes_sbox` finding), so the files are the generator's output byte for byte and the scores below are for that
order. No proof (the proof route for a recursion is the open problem the task is built around; `README.md`
of the task, "Beyond the reference").

Validation: Verilator (`tests/clmul/validate/sim.py DESIGN --width N`): exhaustive at `N = 8`, 2 000 random
pairs at `N = 16, 32` in `tests/run.py` (20 000 with `--full`), no mismatch.
