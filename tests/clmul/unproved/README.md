# `tests/clmul/unproved/`: test material without a proof

Every design the site shows has a kernel-checked proof (decided 2026-11-12), so the designs here are on no page,
chart, table or data file of the site. They stay in the repository as test material: `tests/run.py` checks that the
generator's output is up to date (`layout`) and simulates each file at its own width (`validate`).

- `school_tree_<N>.sv` (N = 8, 16, 32), `kara_b4_<N>.sv` (N = 8, 16, 32), `kara_b2_16.sv`, `kara_b8_16.sv`,
  `kara_full_16.sv`: flat netlists generated by `gen_clmul.py` for ONE width each. Every internal width and index is
  a literal of that N, so no proof of the task's statement (every N in range) can exist for these files. Their
  measured numbers are history in `tasks/clmul/README.md` ("Scores").

Two of the families have proved parametric forms, which the site draws in their place (`tests/clmul/baselines/`):
`clmul_tree.sv` (the schoolbook tree; the same XOR trees as `school_tree_<N>` at N = 1, 2, 4, 8, 16, 32) and
`kara_lv.sv` (the Karatsuba recursion with the 4-bit base, level by level; the same expression trees as `kara_b4_<N>`
at N <= 4 and N = 8, 16, 32). The 2-bit, 8-bit and full-depth Karatsuba files have none yet.
