**svGolf path versus ls-sv.** `extractors/sv/extract.py` takes several files and `-I` directories (`--top T f1.sv f2.sv -I dir`); that is how every
block here was extracted. svGolf's checker does not: `check/envelope.py` runs the SOURCE GATE on ONE file (README: "One file, one design") and extracts
the gate's canonical text; the gate refuses every compiler directive but `timescale and `default_nettype, attributes, `unique`/`priority`, pragma comments
and x/z literals (P-NO-TOOL-DIRECTIVES, P-SAME-PROGRAM). Measured on the 81 primary files below 1 MB: **16 pass the gate as written**; findings by category (files with at least one): directive/macro/include 50, unique/priority 20, attribute 11, x/z literal 10, pragma comment 6.
So multi-file/include/package support is a blocker of the svGolf path (not of ls-sv itself): a real block verified through the checker needs a flattening step
(preprocess + concatenate in dependency order) or a multi-file gate; ls-sv's extractor and loader need nothing new for it.

Per project. EXTRACTS-CLEAN = slang no error and no Unsupported node in the envelope; LOADS-CLEAN = additionally `load_design_sv2` accepts it and the lowered design has no Unsupported node
at the default point (the checker's `design`-stage test). The last column counts blocks that reach LOADS-CLEAN as-is or through a worked-around variant (`@wa`/`@wa2`/`@wa3`).

## 7. Not measured, and caveats

* The Lean steps ran at the DEFAULT parameter point of each block (`d.sem <defaults>`); `load_design_sv2` is the checker's own gate, but the multi-point probe sidecar (`--probe-points`) was not used, so a block that
  loads at its defaults may still be refused at another point.
* A loader refusal reports the FIRST failing message (`load_design_sv2` throws at the first); the blockers behind it are invisible until it is removed. The extractor-side list is complete (all Unsupported nodes).
* `sv_structure?` / `sv_equations?` were run only on blocks that load with a clean lowered design and whose processes are continuous assigns / `always_comb`: the shape of the goal is the task shape
  (`example (p0 ... : Nat) : CombDesign (d.sem p0 ...)`, parameters free), no rank certificate was supplied, so `RECOGNIZED` means the recognizer accepted the design and printed its sites and rank relation, not that a proof exists.
* Sequential blocks (registers, FSM multipliers/dividers) were measured through the loader only; the sequential tier is not an ls-sv goal of the current ladder (policy: combinational first).
* Envelopes above 1.5 MB (13 blocks) were loaded in a separate budgeted batch; blocks that did not finish are reported as `NOT-RUN` / `LOAD-CRASH`, never as accepted.
* The `@wa*` variants are derived by regular expressions (`census_extract.py`: `modernize`, `type_implicit_ports`, `make_slice`) and by one hand edit (`hazard3_branchcmp`: the configuration include replaced by its one parameter).
  They are not part of any claim about the block as written. The modernizer does not touch non-ANSI port declarations or implicit-typed nets declared in the body.
* No simulation oracle (Verilator/Icarus/Xcelium) was run: this is a census of acceptance, not of semantic agreement. The semantic cross-checks of ls-sv (harness/sv) are not repeated here.
* The svGolf source-gate measurement skips the one primary file above 1 MB (the 9.5 MB Rocket file: the gate's Python scanner ran more than 7 minutes on it before I stopped it); 81 of the 82 as-is blocks are measured.
* Third-party licences differ and are recorded per project; nothing third-party is committed. Licence strings come from file headers and GitHub metadata and were not legally reviewed.
