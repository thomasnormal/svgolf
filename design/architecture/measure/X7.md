# X7 preparation: the cost per site of today's route

**Status label:** measurement (heartbeats counted in Lean through the slot; pyslang and the repository's extractor for the
slices). Agent M, WS4, 2026-11-02. Branch `arch-measure`, base `integ1102` at `d5fbdbc4`. ARCH-NOTE §7 X7 asks for
heartbeats per template site for ibex_alu and a slice of ibex_cs_registers, against today's `symExec` route. This file
is the preparation: the baseline on today's route, and the two ibex blocks brought onto that route **as sliced
variants**. The E-derived side of X7 needs E's lenses and is not measured here. Data: [`x7.json`](x7.json).

## The instrument ([`x7_probe.py`](x7_probe.py))

- **Heartbeats** are core Lean's `IO.getNumHeartbeats`, the counter `maxHeartbeats` limits (one `maxHeartbeats` unit is
  1000 heartbeats; "kHB" below is 1000 heartbeats). The probe wraps every top-level command in `count_hb in …`, which
  reads the counter before and after `elabCommand` and prints `X7HB <line> <heartbeats>`. `set_option Elab.async false`
  makes each theorem's elaboration and kernel check run inside its own command, so the count is the declaration's whole
  cost.
- **References: the proofs are not changed.** The probe is the staged proof (`check.py --unproved --stage-dir`; the
  design is compiled by the checker's own design stage) with `count_hb in` inserted before each declaration.
- **Slices: today's route, written out.** `load_design_sv2`; `sv_structure (rank := …)` on
  `∃ d', d.sem.lowerComb = some d' ∧ CombDesign d' ∧ Acyclic d'` (the form `add_proc.lean` uses), the rank being each
  site's depth in the signal dependency graph, computed from the envelope; `sv_equations` in the settled-state context of
  the lowered design, every input port known (`SvState.lookup st "p" = some (LVec.ofBitVec x_p)`, what a task's
  `HoldAll` gives a reference), and its obligations closed by the references' own closers (`intros; omega`,
  `sv_cover`, `inKnown_ofBitVec`). There is no spec, so there is no player arithmetic: this is the route's own cost,
  the part a lens replaces. Both theorems close with axioms `[propext, Classical.choice, Quot.sound]`.
- **Template sites** are what a lens is instantiated per (ARCH-NOTE §4.4): one per continuous assign or `always_comb`
  in the top module's text, a generate body counted once. **Flat sites** are `(d.sem P).processes.size` at the task's
  scoring point `P`.

## B. The two ibex blocks on today's route (all numbers on the sliced variants)

### B.1 Why slices

Neither block reaches today's route as it is (MEASURED with the current extractor and Lean; READ where marked):
- **ibex_alu** (884 lines). Its only parameter is `parameter ibex_pkg::rv32b_e RV32B`, an enum-typed package parameter;
  the `operator_i` port is a package enum; the module imports `ibex_pkg::*`. The envelope carries 3 enum types, which
  the recognizer refuses outright ("enums are outside the v1 fragment", `PDesign.summaryG`, READ). The RV32B generate
  branch `g_alu_rvb` (source lines 333-805) holds all 66 Unsupported nodes of the envelope: `AssignmentExpression:target`
  56, `ElementSelect:default-point-index` 6, `SimpleAssignmentPatternExpression` 4.
- **ibex_cs_registers** (2260 lines, sequential): 147 Unsupported nodes; packed structs, unpacked arrays indexed by a
  signal, `ibex_csr`/`ibex_counter` instances, 20 parameters, several of package types.

### B.2 The slicer ([`x7_slice.py`](x7_slice.py))

Deterministic and recorded, as agreed with the lead:
- **Pinned inputs.** lowRISC/ibex at `f4515520c0` (RB0's commit). Every input file is checked against the sha256 in
  `svgolf/design/real-world-sv/rb0/files.tsv`; a mismatch stops the run.
- **Exact edits.** Each edit names its anchor and how often it must match; package enum values come from pyslang's
  elaboration of `ibex_pkg.sv`; every rewrite carries its equivalence argument in the code and in `transforms.json`, and
  the run stops where the argument's precondition fails (a `unique` that could be violated stays; a parameter or
  constant left in the code after folding stops the run). Two runs into fresh directories gave byte-identical output.
- **Output only under scratch** (`$SP/arch/m-x7/slice/<variant>/`), never in this repository, with `transforms.json`
  beside each output: every edit with its kind, source line (or the package line of the enum it copies), count, and the
  input and output sha256.

**Reading for pricing the package tier** (beside X6's coverage finding: enum-typed parameters 46 and package-scoped
parameters 26 of the 378 refused probe entries):
1. **Most edits are package edits, and each is mechanical.** 100 of 116 ALU edits are package enum constants (97 uses),
   the enum type of one port, the import and the enum-typed parameter. Each is a lookup once the package is elaborated.
2. **The package tier alone does not put ibex_alu on the route** (the control, MEASURED). With every package edit
   applied and nothing else, the recognizer still refuses 11 of 28 plain sites and the conditional generate, and the
   envelope still carries the untaken branch's 66 Unsupported nodes. Fixing the generate branch at the parameter point
   and two exact local rewrites (`unique` over distinct constants, `$unsigned` of an unsigned signal) bring that to 6
   of 37; the last 6 are the procedural-body shape (B.3).
3. **The package tier needs typed constants in the comb fragment, not only in the elaborator** (MEASURED, three
   attempts, then READ). Declaring the constants as `localparam logic [6:0] ALU_ADD = 7'd0` loads but is refused
   ("only `int`/`integer` (32-bit signed) localparams are in the v1 fragment", `lpTypeOk`); declaring them `integer`
   is refused at every use ("width conversion": a 7-bit `operator_i` compared with a 32-bit constant). Only the sized
   literal at each use passes. So a constant of a package enum has no named spelling in today's fragment; X6's list
   (enum-typed parameters, package-scoped parameters) does not cover this.

## D. Verdict

1. **Today's route costs 14-20k kHB per template site on real RTL, on the sliced variants** (MEASURED, B.4): 14.2k on
   `ibex_alu@accepted` (32 template sites: structure 5.6k, equations 8.5k), 19.5k on `ibex_cs_registers@csrop` (11:
   structure 6.6k, equations 12.9k); the transformation lists are in C. The whole reference proofs, which add the
   interface and the player's arithmetic, cost 20.7-46.8k kHB per template site on the five parametric references
   and 5.4k on the two flat 113-site ones (A). ARCH-NOTE's 15.7k kHB per site from the scaling audit is the right order
   for the route alone.
2. **Per flat site is not a lens metric** (MEASURED, A): a parametric proof's cost is fixed while its flat sites grow with
   `N` (`mul_n`: 1026 flat sites at `N = 16`, 0.31k kHB each). This confirms §4.4's choice of template sites.
3. **The X7 comparison point** for E-derived lenses is therefore per template site and for the route only: 14.2k kHB
   on the sliced variant `ibex_alu@accepted` and 19.5k kHB on the sliced variant `ibex_cs_registers@csrop`. The "more than 2× worse" stop rule then means above about 28k and 39k kHB
   per template site, on the same two sliced variants.
4. **ibex_alu reaches today's route only as a slice** (MEASURED, B.3 and C). The package tier is necessary and not
   sufficient: package edits alone leave 11 of 28 sites and the conditional generate refused; the last 6 refusals are the
   procedural-body shape of ibex's `always_comb` style, a WP-PROC/R-PROC item.
